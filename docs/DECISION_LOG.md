## 1. 確定仕様ベースライン一覧（仕様ID 01〜34）

| 仕様ID | 決定内容 | 実装上の必須要件 |
|---|---|---|
| **01** | 全人脈の横断管理 | BNI、仕事、友人、プライベートのタグ管理と区分。共通基盤で管理。 |
| **02** | 多様な面談チャネルの対象化 | Zoom/Meet、対面、電話メモ、LINE貼付、メール。無断傍受は厳禁。 |
| **03** | 対面会話のスマホ録音先行 | 音声入力ソースを抽象化。PWAのOS制約を正直に扱う。 |
| **04** | 会話と公開Web情報の分離補完 | 本人発言とWeb調査を出典別に分離管理。Web情報の自動上書き禁止。 |
| **05** | 音声90日保存・文字起こし永続 | 音声は初期90日で自動破棄。重要音声のみ個別延長。削除請求に対応。 |
| **06** | 高確度のみ自動統合・曖昧なら確認 | 複合キーによる厳格名寄せ。曖昧な場合は確認待ちキューへ。 |
| **07** | 控えめな先回りAI秘書 | 静かな通知、重複抑制、スヌーズ、夜間静音、押し付けない提案。 |
| **08** | 既存人脈の一括取り込み | Google連絡先、CSV/Excel、名刺両面撮影。ドライランと確認を徹底。 |
| **09** | 相関図の2モード切替 | 「確認済み実関係」と「AI紹介候補関係」を明確に分離表示。 |
| **10** | 紹介後の成果追跡 | 未確認の成約・成果を自動確定しない。ユーザー手動確認を必須化。 |
| **11** | BNI全国マスターの階層管理 | 地域・都道府県・リージョン・チャプターの独立管理。手動追加可能。 |
| **12** | 自然言語＋通常検索＋音声入力 | 質問から人物カルテや相関図への遷移。音声非対応時のテキストフォールバック。 |
| **13** | 本人利用先行・SaaS基盤先行 | 初期UIは1人用、DB/APIはマルチテナント（RLS）で完全設計。 |
| **14** | Zoom主催者別の収録分岐 | 自ホストはクラウド録画連携、相手ホストは同意ボットまたは手動取込。 |
| **15** | 説明可能な多軸マッチング | 適合率の単一パーセント表示禁止。地域・専門・実績の根拠を提示。 |
| **16** | 双方確認型の下書き作成 | 紹介文下書きはユーザーが確認・送信。無断自動送信は禁止。 |
| **17** | ダッシュボードとシンプルの切替 | 情報過多を防ぐ2モードUI。ユーザー設定をローカル保持。 |
| **18** | Apple風ミニマル×近未来AI | 上質な余白、繊細なヘアライン、落ち着いた色彩、軽量なPWA。 |
| **19** | 安全ガード付きAIツール実行 | 削除・送信・公開設定などの破壊的変更は必ずユーザー承認を挟む。 |
| **20** | 出典付き関係発見 | 会話中に登場した人間関係は根拠セグメント付きで記録。 |
| **21** | 未登録人物の仮カルテ分離 | 会話内の第三者は `provisional` として実人脈と隔離。 |
| **22** | 項目単位のプライバシー設定 | 私的情報（家族・趣味・健康）は紹介候補から自動遮断。 |
| **23** | 複数会社・事業・役職の保持 | 1人の人物に複数の現在/過去の所属と事業オファリングを紐付け。 |
| **24** | 複数人会話の話者分離 | 話者ラベルと実名同定を分離。不確実な場合は保留。 |
| **25** | 発言者確定情報のみ自動反映 | 誰の発言か曖昧な事実・約束はカルテを更新せず確認待ちへ。 |
